# 产品 UI 镜头：导出真实 DOM（首选）或按源码重建

## 为什么

交互镜头优先使用**真实 DOM + 产品自己的样式体系**：可导出就导出，只有源码就重建纯展示组件。布局、字体、图标和状态来自产品，按绝对帧驱动；位图素材仍受自身分辨率限制。

无法导出 DOM、没有可用源码或需要非 DOM 内容时，按 `real-ui-capture.md` 使用真实状态截图 / 帧序列。截图也是合法成片素材，但不能用文字重影淡变伪装连续操作；有 DOM 的路线则把截图主要作为对照基准。按实际能力选择，不把技术路线当质量结论。

## 首选：产品能跑起来时，直接导出真实 DOM

照源码 className 手写复刻，结构和细节总会漏（窗口外壳、功能页第二栏、输入框上方的状态条、菜单弹出的真实位置……），用户一眼就能看出「和实际差别大」。产品能在本机跑起来（有 CDP / 远程调试端口）时，更可靠的做法是：

1. **连上产品**：优先使用独立账号 / 用户目录的演示实例；`node scripts/cdp.mjs targets` 确认窗口（`CDP_PORT` / `CDP_MATCH` 指定实例和页面）。只有用户明确授权才操作其指定真实实例；不改真实记录，不触发未授权外部操作，记录原页面并在导出后恢复。
2. **操作到目标状态**：`cdp.mjs rect '<选择器>'` 查坐标，`move` 出悬停态、`click` 打开菜单或切页、`key Escape` 关弹层。
3. **导出**：把 `templates/export/export_dom.example.json` 复制到视频工程改成自己的配置，`node scripts/export_dom.mjs <配置.json>`。它会克隆节点（不动页面上的真实节点）、记下窗口里的位置（`data-captured-rect`）、按配置换演示数据、把头像换成占位、修正 `h-screen` / `w-screen`，结果存成 `export const html = "…"` 的 `.ts` 模块。按结构改的演示数据（只留一问一答、复制列表行、换回复正文）写在 transform 文件里，参考 `templates/export/transforms/shell.js`。
4. **查泄露**：配置里的 `forbid` 列出真实姓名、公司、账号，命中就不写文件；脚本还会报邮箱和剩余的 base64 位图（头像常是内嵌照片，只替换外链会漏）。导完再人工 grep 一遍。
5. **渲染与逐帧修改**：视频里用同一套产品 CSS，`templates/remotion/Captured.tsx` 的 `<Cap html mutate>` 渲染；交互状态由 `mutate(root, frame)` 每帧写入**完整的目标状态**（改宽度、加减 class、换图标、逐字写入），不能依赖上一帧。
6. **状态切换先 diff，再确认因果**：收起 / 展开、打开抽屉这类切换，在真实产品里把两端各导出一次，`python3 scripts/diff_dom.py a.ts b.ts` 列出候选差异。按实际触发事件分组，核对真实联动、离散状态及先后关系，再设置独立事件区间；不能把两端差异全交给一个进度。操作编排与原速验证见 `interaction-choreography.md`。

导出时的常见坑（放大后最明显）：
- **挂载视口要用产品原生视口**：导出的片段在视频里放进与产品窗口同尺寸的 iframe（例如 1440×900），再用 CSS zoom 放大；直接挂在 1920×1080 画布里，vh / 断点 / 媒体查询会让布局变样。
- **放大后显眼的线先对照来源**：用相同比例的真实产品基准核对 tab 分隔线、描边与阴影。只有导出、重复挂载或缩放错误额外产生的边线才修正；产品原本存在的线条不能因为放大后显眼就默认删除。若经明确约定做美术简化，记录选择器、前后对照和偏离理由，不冒称逐像素还原。
- 根节点自己带的 `h-screen` / `w-screen`（`querySelectorAll` 不包含根节点）在视频里会按整个画布算尺寸（`export_dom.mjs` 已自动换成 `h-full` / `w-full`）。
- 产品里的 CSS 入场动画在逐帧渲染里停在第一帧（半透明）→ 导出容器内统一 `animation: none; transition: none`。
- 编辑器等第三方组件的样式是运行时注入的 `<style>`（如 CodeMirror 的 `ͼ` 前缀类），不在产品 CSS 文件里，要单独导出注入（配置里的 `runtimeStyles`）。
- Tailwind 按内容扫描类名：导出的 HTML 要放进会被扫描的源码目录（例如存成 `.ts` 字符串模块）。
- 用 CSS `background-image` 的图（缩略图、壁纸）不会被渲染器等待，新镜头第一帧可能空白 → 用隐藏的 `<Img>` 预加载。
- 产品用到的字体（例如正文衬线体）要一起注册，否则画面是本机系统字体在兜底，换机器就变。
- **状态差异不等于同时联动**：收起面板可能联动标题栏内边距和开关样式，必须对照真实产品一起还原；但宽度、透明度、激活状态未必使用同一曲线或同一生效时刻。按事件组分别定义连续变化与离散切换，遵循产品 motion token。独立滑块、不同手柄和分步操作必须使用独立进度，明确未操作属性保持不变。只为取样式而导出的那份，要裁到只剩所需节点，避免保留真实数据。

下面第 1 步（接入产品样式管线）两种做法都要做：导出的 DOM 也靠产品的 CSS 和 Tailwind 类名才能渲染对。拿不到可运行的产品时，再从第 2 步起照源码手写复刻。

## 流程

1. **接入产品样式管线**（一次性）
   - 视频工程里放一份 `tailwind.config`，`require` 产品的配置，只把 `content` 指向视频工程的组件目录。
   - 用产品的 tailwindcss CLI 编译产品全局 CSS（去掉字体 `@import`，相对路径资源改成外链占位）→ `product.css`，在合成根组件里 import。**新增组件后要重新编译**（Tailwind 按 content 扫描类名）。
   - 字体按产品同名字体族用 FontFace 注册（例如 `Inter Variable` + `Noto Sans SC Variable`），配合 `delayRender` 等加载完。
   - webpack `resolve.modules` 追加产品仓库的 `node_modules`，复用 clsx / tailwind-merge / lucide-react；产品自己的图标组件直接复制源文件。
   - 加一条全局规则：`.root *, .root *::before, .root *::after { animation: none !important; transition: none !important; }` —— 产品里的 CSS 动画和过渡在逐帧渲染里不跟随时间轴，全部关掉，动效改由组件按帧计算。

2. **按源码复刻组件**（纯展示）
   - 先把每个要用的组件的 JSX 结构、className、内联 style、token 名、图标名、文案（从 locale 文件取）整理成清单，再写成**纯展示组件**：去掉 store / IPC / 事件，交互状态改成 props（`hover: 0..1`、`open: 0..1`、`press`、`progress`）。
   - className 和内联 style 照抄，不要凭印象写颜色和尺寸；图标名先在图标表里核对存在。
   - 演示内容里的「网页」「生成的应用」这类非产品界面，如果当初是自己写的 HTML，也改写成 React 组件，状态由 props 控制。
   - 需要派生数据（例如图片主题配色）时，用 esbuild 把产品里的纯函数打包出来离线跑一遍，生成 JSON 给视频用，不要手编颜色。

3. **对照校验**：做一个逐帧切换的对照合成，每帧放一个组件，按真实截图的逻辑像素位置摆放，渲染后和截图并排看，间距 / 字号 / 圆角 / 阴影 / 图标对不上就回源码查。

4. **逐帧交互**：动效曲线和时长取产品 motion token（例如 swift 180ms、soft 240ms、spring、菜单 150ms easeOut scale .985→1、子菜单悬停 75ms 后 120ms 弹出、Tooltip 150ms 延迟 + spring）。
   - 打字：按帧截取字符串，光标输入时常亮、停下后闪烁；文件引用 token 算一个输入单位。
   - 菜单 / 子菜单：同一时刻只渲染当前那一个子菜单，旧的立刻消失，新的按 token 弹出 —— 不会有截图淡变的鬼影。
   - 布局变化（打开工作台时会话区收窄）直接插值容器宽度，文字自然重排；消息区用 `flex-end` 底对齐 + 顶部渐隐，内容增长时自然上推，就像真实聊天的「贴底滚动」。
   - 卡片换列：区分系统自动重排与用户拖拽。自动重排由事件触发并遵循产品动效；拖拽期间卡片抓取点跟随指针，松开后才按产品规则吸附，不能各自缓动。抬升与旋转只在真实产品支持时还原，落点按实际网格计算。

5. **抽帧与原速检查**：用 `@remotion/bundler` 只打包一次、`renderStill` 渲染一串指定帧号（`<Freeze>` 包整个成片不可靠，嵌套 Sequence 时帧号会错），拼成网格逐张看；另导出原速操作小样，检查触发、跟手、松开和结果停留。不同文案状态核对按钮的文字 / 图标组合对齐，光标不遮关键反馈；静帧一致不代表操作自然。

## 注意

- 带 `transform-style: preserve-3d` 的元素上**不要直接设 opacity 或 filter**：浏览器会把它拍平成 2D，卡片翻转时正反面同时露出来。淡入淡出和模糊都加在它外面一层包裹元素上。

- `:root` 上用 `var()` 派生的变量（例如 `--action-primary: var(--brand-primary)`）在 `:root` 就解析完了；在子树里覆盖基础色（切主题）时，要把派生变量也重新声明一遍，否则按钮不跟着变色。
- 局部界面优先放大相关组件；整体窗口可交代上下文，但其细字不承担核心阅读。正文在 1080p 下以 18px 为起点，另验素材分辨率和实际投放尺寸；缩放倍数不是可读性结论。设置弹窗等宽内容可在真实支持的布局范围内调整，不能为排版伪造产品状态。
- 光标落点用组件内的逻辑坐标换算（舞台原点 + 逻辑坐标 × 缩放），坐标拿不准就先渲染对照帧量出来。
- 中文字体如果是按文案抽的子集，重建组件带进来大量界面文字后**必须重新抽子集**，否则缺的字静默回退系统字体、字形混杂（加进几十个界面组件后缺上百个字很常见）。渲染前用 fontTools 比对 src 里的字符和字体 cmap。
