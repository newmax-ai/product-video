# 产品宣传视频：从参考到独立设计

本文件提炼从 X 等渠道找到的创作者经验与公开指南，服务于通用产品视频制作。**参考从哪里找到，不决定视频在哪里发布。** 片型、时长、画幅、声音和交付范围按实际任务选择；不默认附加发帖文案、平台运营或增长测试。来源与观察边界见 [研究来源](product-video-sources.md)，原创与复用规则见 [参考素材怎么用](reference-intake.md)。

## 1. 先定观众理解，再组织能力

用一句话写清：**观众应认出什么产品，理解它能带来什么变化，画面凭什么让人相信。**

- 新产品先建立身份与用途；功能更新突出变化；品牌片允许情绪与理念，但不要让它们冒充能力证据。
- 短片可以只讲一个变化；长片可以多章节。各章节支撑同一定位，不强制所有片子只有一个功能或一种结构。
- 每项主张选择最短充分证据：一项真实操作、可辨认的成果或有来源的对照。没有证据的能力先补材料，不靠口号填空。
- 结尾服从片型：品牌收束、成果落定、明确下一步或无缝循环都可以，不强迫每支片有 CTA。

## 2. 开场给观看理由，后续兑现

可在既有美术方向里比较不同开场；不额外要求多套整片。以下是自拟的结构选项，不是来源视频的镜头复制：

| 方式 | 适用条件 | 必须兑现 | 误用 |
|------|----------|----------|------|
| 结果先行 | 成果可辨认且来源可信 | 说明产品与成果的关系 | 只见漂亮作品，不知道宣传谁 |
| 痛点对照 | 受众熟悉原流程 | 在一致条件下展示真实变化 | 虚构竞品缺点或提速数字 |
| 动作中切入 | 关键动作本身有表现力 | 补足对象、用途与结果 | 没上下文的任意软件录屏 |
| 悬念与揭示 | 隐藏信息能引出产品特性 | 在叙事中及时回答悬念 | 用炫技开场拖延产品内容 |

首帧不必运动，不必大标题，也不一概禁止品牌；要避免无信息的片头。产品可以通过真实界面、字标、成果归属或简短定位被认出，不必为品牌单独插一页。具体秒数按片型与节奏安排，不从某条热帖推出统一时长。

## 3. 把 UI 做成变化的故事，而非点击清单

每个能力段先写：**同一对象的原状态 → 必要动作 → 新状态 → 用户所得**，再设计镜头。

- 保持对象身份连续：项目、文件、选区或成果前后对应。观众能跟住“什么被改变了”，不靠解释长段文案补关系。
- 从获授权的真实产品提取内容、必要控件与反馈，在外层重新编排尺度与层次；整窗交代上下文，细节镜头承载阅读。既不把完整窗口缩成不可读贴图，也不把孤立按钮放大就当设计。
- 宣传片可以省略重复输入、导航与等待，不必教会全部操作；但重要设置、人工加工与限制不能隐去。压缩等待明确说明，不伪造瞬时完成。
- 标题表达意义，界面展示动作，成果证明能力。每镜设主焦点，让文字和画面互补，不同时叠满口号、字幕和提示。
- 增加案例或功能必须有新增信息：扩展适用范围、推进故事或构成对照；不能用重复作品虚构规模，也不把两个成功示例当普遍成功率。

来源 X1–X3 提供承诺、过程与结果的文字经验；X5 支持用真实设计系统组件迭代 demo 的思路，不提供本 Skill 的实现代码，也不证明任意方案具有逐帧确定性。

## 4. 镜头、维度与节奏共同服务信息

以下是结合现有制作流程形成的设计规则，不冒充本轮未观看案例的逐镜结论：

- **转场交接信息**：上一镜的成果成为下一镜的输入，局部细节回到整体，或用一致条件形成前后对照。硬切也可以有效；转场复杂度不是质量指标。
- **按任务选择维度**：2D 服务阅读和操作，2.5D 建立层级，真实 3D 展示空间关系与体积。把二维截图转斜不是空间设计，空间运动也不能遮住证据。
- **动静有不同职责**：建立对象、发生动作、揭示结果、阅读落定各有节奏；阅读区域稳定，操作保持真实手感，不把所有元素从头到尾一起移动。
- **音乐不只给剪切点**：用乐句组织段落，让关键动作结果与音乐释放相呼应；不为踩拍延迟反馈，也不靠慢放操作、漂浮或空停留填满时长。
- **视觉统一但不重复**：共享品牌字体、色彩和材质角色，变化来自构图、疏密、尺度与镜头职责，不是每一页套同一张卡片。

具体执行继续使用 `creative-direction.md`、`motion-and-type.md` 和 `three-workflow.md`，交互按分镜中的事件与状态清单检查，不另建一套冲突的制作流程。

## 5. 用实际观看诊断，不用热度替代判断

在原有动态样片关和全片验收内检查，不新增固定审批：

| 观察到的问题 | 优先诊断 |
|--------------|----------|
| 不知道宣传谁 | 产品、演示对象和成果身份是否混淆，品牌信息是否与内容脱节 |
| 只记得动画 | 主张是否有可见证据，镜头运动是否压过关键变化 |
| 看不懂能力 | 输入、必要动作、结果之间是否缺因果或上下文 |
| 字多 / 太快 | 焦点、层级、尺度与镜头信息量，再调整局部阅读时间 |
| 节奏拖沓 | 动作完成后是否空等，段落是否只有一种速度，音乐是否真正参与结构 |
| 像在复刻别人 | 文案、构图、时序和独特转场是否一起照搬，是否缺本产品自己的关系与母题 |

按实际观看场景检查显示尺度与压缩后的清晰度；静音审看用于检查视觉主线，配音片另验字幕，有声音的版本另验音画关系。不要因参考来自手机信息流就默认交付竖屏或小屏版。

让实际观察者复述“是什么产品、做成了什么、画面证明了什么”，记录具体误解后修对应镜头；没有实际审看则标待验证。需要比较改法时，固定其他条件，做小范围样片对照，不默认开启平台 A/B 测试。播放量、点赞或创作者自报收入不能证明某个镜头设计有效。

## 6. 将研究记录转成原创方案

写出一条可追溯链：**来源里的观察 / 作者经验 → 可迁移原则 → 本产品的具体设计 → 实际样片验证**。只取得文字就停在文字层证据，不补写未看过的构图、镜头时间码或运动轨迹。

例如，可借鉴“先亮成果，再补关键过程”的叙事方法，但成果、文案、对象关系、构图、时间轴与实现由本产品事实重新设计。不复制参考资产、整套分镜或第三方 Git 工程换皮；合法依赖复用也要如实标明来源和许可。
