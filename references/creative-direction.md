# 美术方向：从视觉母题到镜头系统

目标不是把默认片子换成品牌色，而是让观众在无声、无标题时也能认出它的视觉逻辑。先做方向，再做整片；本文件补充 `SKILL.md` 的确认点 1，不增加新的用户确认。

## 1. 提出 2–3 个真正不同的方向

使用相同的产品主张、真实 UI / 作品和约定画幅作对照。每个方向给出：

| 项 | 要回答什么 |
|----|------------|
| 方向名 + 一句话 | 具体设计概念，例如“有序档案”“精密舞台”“流动工作台”，不只写“高级、科技” |
| 视觉母题 | 哪个形状、关系或行为反复出现；它如何来自产品的真实能力 |
| 构图 / 密度 | 主体在哪里、主次比例、留白方向；稀疏与密集段落如何交替 |
| 空间 | 平面、分层或真实体积为何必要；前中后景、遮挡、透视如何安排 |
| 材质 / 光影 | 纸、哑光、金属、透明体等各承担什么角色；主光、环境光、接触阴影如何塑形 |
| 镜头语言 | 固定、推近、侧移、绕行或正交切换；每次运动要揭示什么 |
| 排版 / 节奏 | 网格、字体角色、标题与 UI 关系；展现、动作、阅读停留如何分配 |
| 真实证据 | 哪个界面状态 / 结果能证明这条能力；哪些只是品牌表达 |
| 风险 / 成本 | 素材是否齐、3D / 导出复杂度、移动端可读性、替代方案 |

**代表性静帧**：每方向至少渲染 1 张能体现构图、空间和材质的帧，优先选同一个核心能力镜头；方向含关键 3D 时必须有其空间静帧，不能只给色板。可再给品牌亮相或成果展示帧。静帧属于轻量方案原型，不先做全片动画，也不假称已通过渲染测试。

将方向并排、标注对应参考、说明推荐理由。确认点 1 一次提交方向静帧、主推分镜、素材缺项与配乐方案，让用户在这里选择；不先问“选哪种色”再问“选哪种空间”再问分镜。用户已有明确参考时，候选仍需有有意义的差别，但可围绕既定品牌约束提出。

## 2. 从参考提炼规则，不复制表面

先按 `reference-intake.md` 拆镜头，再记录：

- **拿什么**：例如偏心构图、巨大主体与小注释的尺度差、斜向光形成体积、密集成果段之后的空镜停留。
- **不拿什么**：竞品 logo / UI / 文案 / 专有图形、无授权模型，以及不符合本产品的效果承诺。
- **如何转译**：将参考里的展示对象换成真实产品能力，保留构图或节奏规律，改成自己的母题和品牌材质。

方向静帧和参考按相同比例并排看。比较层级、尺度、空间和节奏，不以“颜色相似”代替设计判断；注明参考素材授权边界，不把其用户案例搬成自己的证据。

## 3. 建立视觉系统，不建立重复模板

### 视觉母题

选一个能随叙事演变的母题，例如：输入汇聚成一个工作台、工具沿轨道切换、成果从抽屉展开、内容按证据层归档。母题可出现在 logo 构图、UI 分层、转场和结尾，但不要求每帧都出现同一装饰。

避免与功能无关的轨道、粒子、能量场。抽象舞台只是表达，不暗示真实产品拥有不存在的硬件、3D 功能或性能。

### 构图与密度

- 每镜头先画主、中、次三级尺度关系；核心 UI 或成果是主角，装饰不能抢占阅读面积。
- 选网格与锚点：居中、偏心、左右对照、上下路径等按内容变化。镜头之间共享对齐逻辑，不必共享同一种布局。
- 安排密度波形：稀疏亮相 → 聚焦操作 → 密集成果 → 清晰落版。丰富度来自可解释的主次，不是数量越多越好，也不是一律删到只剩标题。
- 实际投放尺寸看细字；侧倾、透视与景深不能让核心 UI 变成无法阅读的纹理。

### 产品主题与对比

- 产品 UI 使用自带且符合方向的主题。DOM 路线可保留壁纸；截图拆组件时可切产品纯色主题以免边缘带入背景，注明采集处理，不把纯色推广成所有镜头的要求。
- 舞台与 UI 用明度、色相、尺度和构图建立分离，在灰度联系表核对。投影、描边或透明材料可辅助空间和品牌表达，但不独自承担层级，不为修补主次而盲叠面板。

### 光与焦点

- 阅读段保持清晰焦点；主体可由亮度、轮廓、尺度或色相突出，不必永远是最亮点。暗场与剪影必须有表达目的，不能损害信息阅读。
- 不用无信息的全局压暗填时长；过渡可以静止或运动，按叙事选择，不强制光扫。
- 收尾有明确重点，动作可选。非循环宣传片落版完整停 3–4 秒可作起点；循环片改验首尾接缝，不套落版规则。

### 材质与光影

建立材质角色表：背景是环境，主体表面负责塑形，UI 内容保持真实色彩，强调材料只在关键关系处出现。控制粗糙度、反射、透明与厚度之间的差异，不能所有对象都用同一种玻璃。

至少能解释主光方向、环境亮度和接触关系。阴影、反射与遮挡帮助读懂空间；不是加一圈辉光就叫质感。风景、纹理、模型、HDR 环境资源都需查授权；不存在素材时可用明确标注的程序化几何，不伪造产品实物。

## 4. 逐镜选择 2D / 2.5D / 3D

| 维度 | 最适合 | 不适合 / 边界 |
|------|--------|--------------|
| 2D | 真 UI 操作、短标题、细字阅读、图表解释、对照与 CTA | 不必为了“高级”强加透视 |
| 2.5D | UI 层级分离、轻视差、平面成果展、已知前后顺序的过渡 | CSS 旋转卡片不等于真实几何 / 材质 / 灯光 |
| 真实 3D | 主体亮相、真实体积与遮挡、材质变化、空间成果展、相机在场景中移动 | 不做全片默认选项；绕卡片转一圈不等于空间设计 |

品牌 / 发布 / 版本更新片：至少一个方向默认含真实 3D 镜头（主体亮相、相机穿过空间的转场、落版），在确认点 1 一起给静帧；用户没提也要提出。

每个 3D 镜头写一句“没有空间就讲不清 / 体验不到什么”；答不上来，优先回到 2D 或 2.5D。至少明确主体几何、前中后景、材质与灯光、相机路径、落定构图和回到真实 UI 的方式。空间镜头配方见 `scene-library.md` G1–G4；工程入口见 `three-workflow.md` 和 `templates/three/`。

**三维展示与能力演示分工**：空间段建立整体关系与视觉记忆，正视 UI 段交代真实操作和结果。将真实 DOM / 源码重建状态作为空间表面的来源；不临时画一张“像 UI”的假面板。UI 进入 / 退出空间时的尺寸、位置、裁切、颜色和状态必须匹配。

## 5. 镜头与运动要有意图

- 固定镜头用于阅读与比较；推近用于聚焦；侧移用于揭示层级；绕行用于读出体积；拉远用于展示成果之间的关系。
- 开始构图、结束构图、路径和停留都先定；同一镜头不要同时漂卡片、漂背景、转相机而没有视觉锚点。
- UI 反馈可用 `motion.js` 弹簧；排版、相机与路径按意图用确定性曲线。不是所有对象都有弹性，也不是固定曲线天然廉价。
- 音乐帮助组织段落和重点；操作因果、文本读完和成果看清不被节拍压缩。有意静止是设计的一部分，停留期间可完全不动。
- 景深、运动模糊、折射、辉光只在有理由且不影响主信息时使用；不能用模糊隐藏粗糙模型或低分辨率 UI。

## 6. 不够高级时，先诊断再改

按顺序看，不先减元素：

1. **层级**：主角是否明显、标题和 UI 是否争夺视线？调整比例、位置与对比。
2. **构图 / 密度**：元素关系是否成立，留白是否有方向，密集段是否被组织？用网格、分组与节奏解决，必要时才删无作用元素。
3. **空间 / 材质**：物体有体积、接触和材质差异吗？调整几何、灯光、粗糙度与影子；不是一律改成毛玻璃。
4. **镜头 / 节奏**：相机是否揭示信息、运动是否过满、是否给结果留了阅读时间？减少无目的动作，保留必要变化与停顿。
5. **品牌 / 证据**：只有好看的外壳而没有真实产品吗？回到真实界面和产出；不要把品牌原则写成“已验证效果”。

## 7. 方向与整片验收

- 黑白缩略图看主次、对比和主体轮廓；去掉颜色后仍有清晰视觉中心。
- 整片联系表看构图、密度、明暗和空间分配；不是一路居中字，也不是一路旋转面板。
- 参考并排看层级、尺度、空间、材质与光影，能说明转译方式和差距。
- 正常速度有声 / 静音各看一次：前者看节奏与音乐，后者看叙事和阅读；不靠逐帧截图掩盖晕镜、停留太短或状态不连贯。
- 空间镜头单独查遮挡、景深、反射、UI 清晰度、相机动机和回 UI 衔接；具体清单见 `qa-checklist.md`。

将观察写入工程 `CRITIQUE.md`。代表静帧好看不等于整片已通过；没有实际检查的项目标为待验证。
